# roc-remote 0.1.1

此版本延续 v0.1.0 的
roc-remote 名称与协议，重点调整 NSH 原生控制端的连接页和会话布局。

- 原生连接页采用聚焦邀请输入的原生布局，不再照搬 Web 卡片。
- 连接后显示紧凑工具栏，持续提供工作区导航、连接状态和断开操作；桌面画布填满剩余工作区。
- 显示器选择与开始/停止查看保留在画布旁，Find displays、Capture once、保存图片和发送文字等低频操作收进 Tools。
- 保存图片使用系统保存对话框，取消不写入，已有文件不覆盖；连接本身不会启动远端 capture 或启用输入。
- 桌面控件最小高度为 32 点；Android 查看器保留 48 点触摸目标，仍是实验性 ARM64 只读入口。
- 工作区、Web、Cloudflare 包版本统一为 0.1.1，NSH 清单 build 为 2；TMP 及依赖版本不随产品版本升级。
- 原生截图使用隔离 Xvfb `:101`、1280×720 中实际运行的 v0.1.1 Linux GTK/X11 应用。会话连接真实 localhost relay 与 host，host 授予 desktop 权限，但无 capture 请求、未启用 input，画面不含 secret；不代表物理桌面、远端画面或 Android 真机验收。

**本地验证：** `scripts/check.sh`、36 项 native tests 与 native Clippy，
以及 CLI E2E、Chromium→Rust 联调、7 项 browser E2E 和 relay-pair 均通过。
Android v0.1.1 build 2 ARM64 debug APK 已在本地构建；该包的 `aapt` 元数据、
签名与 alignment 核验另行记录于 `docs/android.md`，不沿用旧试包的核验结果。

**安全与验证边界：** 所有权限默认关闭。邀请含有会话密钥，请勿公开；启用 Shell
相当于授权以主机进程用户身份执行命令。文件操作限制在打开的共享目录能力内，上传仍需
精确大小、FIN 和原子拒覆盖提交，失败或取消时清理暂存文件。JPEG 桌面流仍属实验性功能。
上述仅为本地证据，不代表托管构建完成、物理桌面或多 OS 运行验收。
桌面二进制为 unsigned，macOS 未公证；Android 本地试包使用 Android Debug 签名，
不等于正式发行签名，也没有真机验收声明。不包含 live Cloudflare 部署声明。

## Downloads

Desktop release targets: Windows x64, macOS Intel/Apple Silicon, Linux x64/ARM64.
GitHub Actions produces per-platform/product archives and checksums; consult
the release assets and workflow results for hosted build evidence.

- `roc-remote`: desktop host and CLI.
- `roc-remote-headless`: CLI without capture, input, clipboard or NSH dependencies.
- `roc-remote-native`: native NSH controller.
- `roc-remote-relay`: self-hosted encrypted-traffic relay.
- `roc-remote-web`: compiled static browser client.

The desktop and headless archives both contain a `roc-remote` executable.
Preserve the archive's `branding/` directory beside the Windows native executable
for its window/taskbar icon. These are raw executable archives, not installers or
macOS application bundles. Android remains an experimental read-only viewer;
a local debug APK is not a signed production desktop download or device-test evidence.

Desktop binaries are unsigned and macOS builds are not notarized. Use
`SHA256SUMS` to check download integrity; it is not a publisher signature.
Local checks and end-to-end results are recorded separately from hosted platform
builds and actual OS runtime evidence. No Android device or multi-OS runtime
acceptance, production Android signing or live Cloudflare deployment is claimed.
TMP remains transport-independent and unchanged. All service permissions default
off, and relays do not terminate application encryption.
